## Architectural Decision Records

ADRs document significant protocol and tooling decisions. They live under **Guides** so the process sits with how we build.

## Served ADRs

| # | Title | Status |
|---|-------|--------|
| 1 | [Standard Template and Design Guidelines for ADRs](/docs/guides/adrs/adr/1) | Accepted |

Only **ADR-1** (template and process) is published. Drafts stay in the repo under `drafts/adrs/` and are not served.

## Proposing a new ADR

1. Author from the [ADR-1 template](/docs/guides/adrs/adr/1)
2. Open a PR; allow review
3. Security sign-off for crypto-related ADRs
4. Maintainers set Accepted / Rejected
5. When accepted, add the file under `content/docs/guides/adrs/adr/` and list it here
